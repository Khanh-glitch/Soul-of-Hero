## D19 source extraction method — what this does and does not prove

`source19/*.rgba.gz` are raw 480×270 RGBA8 additive framebuffer dumps, with row-major top-left origin. They are not opaque diagnostic screenshots and are **not brightness-keyed**. `tools/arcana20_join/r32_extract_d.cjs` loads the elected local `original_source/package/handoff/reference/ARCANA_19_Reference_With_Exit.html` (SHA-256 `4d249d53d81c5ff699ebd606983c27b333f7be903fc949ceeb4dd55504a63291`), initializes the real spell 19, advances its real state/pool sequentially at 60 Hz and samples ticks 1,120,240,360,456,489,516,546,570,588. Source shader draws the actual generated sprites/ribbons/quads into cleared transparent framebuffers; their additive RGB is composited into the held SOH frame without a brightness mask, scaling 1 source pixel to 1 SOH pixel, moving source center (244,132) to (746,381). RGB channels are already 8-bit clipped; body gain 1.15, center gain 0.85 then bounded add to the recorded world. Actor masking is manual. This is a diagnostic adaptation, not the complete source renderer, a faithful A capture or a proposed final LDR transfer.

The extractor separates the body from center via call-site/argument heuristics: center STAR/SOFT at `(244,132)`, quads and center-origin two-point filaments vs remaining nodes/graph/pulses/particles. A late OUT STAR can also match (three center sprites at ticks 546/570); `source19/counts.json` records counts. It copies the original generated batch vertices/instances after the real reference OUT alters them, not fabricated geometry. It cannot distinguish all source roles, has no verified per-role coverage, and batching/8-bit clipping loses the original combined saturation and cross-layer blend behavior. It omits source bloom, source scene, camera shake, warp, persistent decal, global flash and post-process. Its temporal data include the **reference OUT study** 8.66–9.76 s, which the source file explicitly marks as a fusion reference addition, not original D; the native D authored OUT is 8.6–9.8 s and is not reproduced here. The source 8.15 s flash event fires in the simulation but is not composited. As a result, the outputs do not demonstrate source A fidelity, exact native timing/OUT, peak motion, original post-processing, or successful A/B/A restoration. Existing native A/B/A-restored evidence remains `renderer/reviews/r30_followup/`, not modified here. No B19 implementation acceptance is claimed.

## Reproduction

The deliverable is self-contained; no build is required to open the page. For investigation, regenerate D fields with the script named above, passing absolute paths to the reference HTML and a writable output directory. It requires Node, `playwright-core`, `@sparticuz/chromium` and WebGL2; platform-specific Chromium libraries may also be required. The script changes no source file. To reproduce the paintovers use `python tools/arcana20_join/r32_make_art.py --base /path/to/decoded_frames` with Pillow and NumPy, where `N13-normal/frame-01.png` and `N13-dimmed/frame-01.png` are the decoded first video frames and the tracked `source19` dumps exist. Software rendering can differ by driver; compare only within the disclosed capture environment. Frame hashes, dimensions and the review hold, not CI success, govern this handoff.
