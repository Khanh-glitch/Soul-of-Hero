# ARCANA20 web integration — WORK IN PROGRESS, NOT PLAYTEST READY

The isolated reference-game derivative now has **experimental combat prototypes** for 20 Core items, but the requested complete build does not yet exist. **Do not publish a play-now link**: only seven source-derived effects have experimental developer-only paths, without P0 fidelity validation; the other attacks currently have no visible skill effect or telegraph. They are unsuitable for playtesting. New isolated diagnostic runs start with all 20 items, with #17–#20 in hotbar slots 4–7; an internal fixture menu can add more. Existing saves are not automatically changed, and there is no production distribution path. Item icons reuse the original icon with numbered notches; they are not final Core art. No quality modes, validated world compositing, P0 parity or target-device performance results exist. This is not production SOH or approved game balance.

## Implemented so far

- `src/game/arcana20.ts`: 20 experimental timed impact plans, inspired by names/climax metadata, using circle, line, expanding ring and multi-hit patterns. Damage values, geometry and slow are newly proposed gameplay, **not P0 combat or game canon**. The use of catalog peak times is provisional and has not been synchronized to actual source/fusion visuals. Distinct patterns are not proof that the final skills have adequate individual identity or balance.
- `src/game/catalog.ts`, `sim.ts`: 20 real nonstackable charge-bearing Core items use the original hotbar/charge commit/cancel path; on release their actual player-owned scheduled collision volumes use the existing `damageCreature` path, not manufactured hit receipts. Pending volumes are scoped to the originating run. No loot/reward route, craft, test inventory UX or item balancing has been added.
- `art.ts`: temporary icon variants, not creator-approved art. `render.ts`: new hit volumes intentionally not drawn as fake generic P0 visuals. Until the complete genuine renderer is integrated, **casting is visually incomplete and dangerous**.

## Subsequent progress: B/C renderer experiments (still not playtest ready)

The developer-only switch `?arcanaBdev=1` now exercises source-derived visual paths for **#02, #03, #08, #07, #10 and #17**, on the live terrain below sorted actors. This is partial work, not a completed P0 port: algorithms come from the historical original B/C TypeScript source and field handling is adapted from the P0 B/C world passes. Code lives in `src/arcana_b/` and `src/arcana_c/`; the copied authoring sources are isolated, not replacements for the original historical files. P0 may differ in timing, floating point, clipping and reworked details. No #05 A/B, #19 A, A+D, NEW or fusion implementation is supplied. No visual acceptance, P0 matched-frame comparison or HUD/actor/occlusion approval has happened.

- Both source pipelines track authored coverage explicitly, including genuinely dark/black ink. B carries decals, shadow, lighting, ordered warp fields and tone math; C carries ground, ink, signed light, displacement, live-world fragment coordinates, plus metadata for whole-stage operations. No scene background is substituted or brightness-keyed.
- The C player advances fixed ticks, and the original nondeterministic particle default is replaced with a per-cast deterministic counter. Thunderloom's original random spark uses P0's dedicated seed 999. This per-cast seed ownership differs from the P0 global counter when effects overlap. C #17 live fragments sample actual terrain; stage blackout and C #10 stage shading have preliminary developer-only owner handling; ordering, LDR blending and overlapping casts are not validated. Screen flash/shake/chroma/bloom are not integrated. The source-C diagnostic is therefore materially incomplete. B global flash/shake is likewise not applied. No production renderer or High mode is provided.
- Combat timing/positions for #02, #03, #07, #08, #10 and #17 were adjusted toward source events and anchors; these damage mechanics remain proposals, not P0 combat. #03 spawns eight hit volumes at the original eight meteor impact times and mapped positions. Collisions are still not creator-approved or visually validated against the final game.
- `?arcanaBdev=1&arcanaGpu=1` opts into a separate experimental WebGL2 field composite for B/C; failure falls back to the CPU field. It is not enabled in production and is **not** an exact High profile. Tests compare selected 384×216 synthetic-scene fixed frames with the corresponding CPU implementation: B #02/#03/#08 and C #07/#10/#17 had maximum channel error 1/255, with nonzero changed pixel counts. This is an implementation comparison, not comparison against P0 or proof for all frames/devices. Full-scene and cropped CPU results matched byte-for-byte in six fixed test scenes; this is similarly bounded evidence only.
- `npm test`: 59/59 pass (13 original, 24 combat/fixture, 22 B/C/ROI tests); `npm run build` and `tsc --noEmit` pass. Browser diagnostics started real #02 and #07 casts and confirmed a charge spent without page exceptions, but #03/#08/#10/#17 were sampled from source modules at fixed times, not mouse-cast through the whole game. Earlier browser startup timed out intermittently and a subsequent run passed.
- Headless Chromium/SwiftShader diagnostic, **tiny uncontrolled samples and not hardware GPU or FPS**: before ROI changes, a live #02 CPU field pass including Canvas read/write was ~60–80 ms after a ~2495 ms first read; a later GPU diagnostic run measured ~4–10 ms after a ~47 ms first pass. A live #07 GPU diagnostic run measured ~8–21 ms after ~29 ms initial. Separate CPU/GPU runs and frame phases are not controlled like-for-like comparisons; concurrent later CPU samples were noisier. This does not establish smoothness, latency, parity, target-device FPS, or an optimization suitable for shipping. Profile full timelines, overlaps, and hardware after the incomplete renderer is finished.

The developer switch is deliberately unavailable in production builds. The remaining 14 designs and all fusions, P0 full fidelity, quality modes, final art, non-debug Core acquisition/selection, remaining post effects, safe gameplay alignment and end-to-end playtest are still outstanding. Do not distribute a link yet.
