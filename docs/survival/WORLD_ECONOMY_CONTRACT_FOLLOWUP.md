## Implemented, with proof limits

- `web/src/game/map-package.ts` + `world.ts` discover source-controlled `web/src/map-packages/*.json` at build time. Independently authored packages are validated, copied, compiled by the unchanged v3 source generator and selectable in the actual title/runtime. Distinct revisions of one map coexist as `id@revision`, with duplicate ID/revision and built-in name collisions rejected. Invalid files produce title diagnostics instead of silently substituting a map. No separate playable map has been supplied and none was manufactured here. The integration test uses a shipping-geometry clone only to exercise the loader, **not** as alternate-map acceptance. A temporary production build containing that JSON was also tested in Chromium: select its map, move, save and reload with its pinned identity. The fixture is deliberately not committed as a playable map.
- Runtime is explicitly limited to 200×200 tiles of 16 pixels, 16 existing zone codes and the six known Elder IDs; renderer, minimap, physics and content are not dimension-agnostic. A mismatched package is rejected, not cropped/rescaled. Terrain and freshness rasters, buildings, static finite loot/cash/vendor/evacuation/door/generator entities, places, starts and detailed geographic descriptor are required. POI gate/generator/loot descriptors must point at matching physical entities. Road width is checked as a raster cross-section along authored centerline tiles; that is not evidence that a cart can sweep through turns or that every POI or hazard is traversable.
- Imported foot/build/cart masks now affect the actual collision/build runtime, with dynamic doors still physically openable. Authored protected paths cannot be built over. A loaded-cart tick test confirms an authored cargo restriction stops both cart and rope; it uses a controlled clone fixture, not the external map or a complete cargo journey. For the shipping and dev layouts, `access-corridors.ts` derives conservative no-build masks from existing static access points to existing reachable roads, without moving terrain or sources. Shipping: 25 connected, 5 unconnected static access points; +177 protected cells, of which 82 were otherwise buildable. Dev: 28 connected, 8 unconnected; +180 cells, 99 otherwise buildable. These grid-derived masks use the v3 baseline source grid even in legacy v1/v2 runs; they protect future construction, not existing player structures or every cargo turn/escape. They do not prove a route through locked doors. `node scripts/access-report.mjs` reproduces the counts.
- `tests/home-sites-physical.test.ts` walks from three distinct shipping starts to three different legal sites and actually places a claim and owned chest. Creatures are disabled and construction materials injected; shelter quality, hauling/loading access, hazards and human preference were not established.
- The collision-resolved `tests/escrow-route-physical.test.ts` walks from a real shipping start to the Trading Post cash chest, takes its 36 physical Ragnarok cash, reaches the seller, spends 30, places an owned claim and escrow, and deposits the remaining 6; it saves/reloads and tests that re-filling the already-minted chest is rejected. **Controlled fixture:** sets the run to the Ragnarok phase, disables creatures and injects the 10 wood/5 stone for the claim. It is not a natural survival route or proof of harvesting those materials, no human enjoyment claim.
- Finite POI loot/cash transfers, gates, generators and vendor purchases require an unobstructed sampled interaction segment. A closed-wall vault-transfer regression checks that proximity alone cannot bypass that wall; it does not prove all interactions or corner geometries.
- `tests/poi-route-physical.test.ts` walks with actual simulation collision on existing `dev_delta` from a start into the relay's outer cache, transfers the physical keycard/fuel, traverses the keycard door, funds the generator, opens the power gate, takes physical vault ingots, retreats outside and reloads. Creatures are disabled; this is a development-layout integration test, not the separately authored map, not shipping's Foundry, and not proof of every POI or hazard. No forced quest/progression was introduced.
- New v3 saves validate source stock/HP against the actual source cell and validate that authored finite cash/loot containers have not been refilled. Existing legacy saves are not reinterpreted or retrofitted with guessed stock. This is bounded source and container validation, **not full item-by-item provenance across fungible stack merges** and not anti-cheat.

## Economics and version policy

The v3 source compiler and its shipping digest `03d4962c` are unchanged. Thus the original comparable forest 40.62 → 16.13 wood nodes per 100 eligible cells and roadside scrap 12.33 → 16.14 per 100 cargo-road edges remain unchanged. We did not silently refill or redistribute already-started runs, or pretend those figures settle balance. A future density change requires an explicitly pinned new source-rules version plus route, yield, competing-use and player testing; the current timber/salvage mix is still a tuning question. The prior metrics' buildable-cell counts predate the new additional access mask.

Tunable cart multipliers are now road 1.36 (was 1.05), off-road 0.72 (was 0.55), rough 0.42 (was 0.32); cargo weight and overload still apply. Pulling no longer bypasses personal carried-load, slow or root penalties. These changes affect existing as well as new runs; they do **not** alter source or map identities. The same estimated empty-out/120-kg-loaded-return shortest-tile paths report s0 cart 111.2 → 85.1 s vs foot 99.6; s1 123.0 → 94.0 vs 122.6; s2 107.6 → 82.2 vs 83.8; s3 32.8 → 25.1 vs 19.7. `WORLD_ECONOMY_HAUL.json` is the old result and `WORLD_ECONOMY_HAUL_AFTER.json` the new result. Times ignore continuous turning/rope, loading, obstacles, path selection, input and wear, and the assumed empty personal inventory is favorable to the cart. The local close foot option is still faster; these are diagnostics, not proven balance or a real loaded journey.

New saves pin map ID/revision/seed, source-rules version, source digest and a separate digest covering terrain, old source rasters, current sources, climate/passability masks, buildings, statics/loot and places plus an imported package's contract. The hashes detect accidental mismatches, not hostile edits. Built-in legacy v1/v2 and earlier v3 saves without a geometry digest are accepted only against frozen `2d4cfdc` built-in geometry fingerprints. An imported save cannot load if its exact `id@revision` is absent or changed. Retain old package revisions and v3 rules in the build until an explicit state/custody migration is designed and tested; do not overwrite package files under an existing revision. Rollback to old applications is unsupported; back up browser storage. Current footprint masks are conservative, and old buildings are retained rather than moved. Hashes do not authenticate saves or ensure historical lineage of merged fungible items.

## Map Agent handoff

Own and supply real map data, not an agent-generated stand-in:

1. A `RuntimeMapPackage` JSON matching `web/src/game/map-package.ts`, under `web/src/map-packages/`, unique stable ID/revision/seed and supported runtime dimensions. `geometry.economy` must provide authoritative biome, elevation/slope, moisture/temperature, fresh/coast, walk/build/cart, road, protected and industrial fields with consistent rasters. Roads and bridges must be physically authored; route masks must agree with actual passability.
2. `geometry.roads`, `pois`, `criticalPaths`, `buildSites`, `nonbossCashSites`, `vendorSites`, and `evacuationSites` must describe real owned geometry and physical statics. Provide road widths/turning clearances, bridges, loading cells, building footprints, entrances, walkable rooms, doors and actual key/fuel/power relations, exterior/deep finite loot, hazards and retreat routes. The runtime presently checks parts of this contract, not cart swept width, alternate escape or economic fairness. It still needs stronger connectivity/width/POI semantic validation before accepting a map as playable.
3. Keep each released revision and its source compiler available. Report missing geometry; never synthesize cash, doors, POIs, water, roads or fallback resources to make checks pass. The owner should identify at least three distinct physically legal home/load sites and routes; a named biome or coordinates do not grant advantages or hidden raids.

## Evidence and remaining blockers

After the changes: TypeScript and production build passed, 142 focused/full-suite tests passed, npm audit reported zero vulnerabilities. Real Chromium normal-input tests covered fresh movement, berry use, crafting/inventory/save/reload and separate natural walk-and-bush harvest. Real earlier `2d4cfdc` v3 and `0333dee` v2 executables each created an early save that continued through the candidate and reload with identity, position, inventory UIDs, entities, source deltas and knowledge compared. These early browser saves did not cover real queued jobs, loaded carts, burnt/depleted sources or gate histories; the focused unit suite separately exercises some of those cases, not a complete cross-version browser audit. Real captures at both sizes are in `web/evidence/economy-contract/`; no generic UI redesign was attempted and 640×360 text remains small.

Outstanding: no actual separately authored playable map, no complete semantic validation of road swept width or all gate/retreat connectivity, no physical loaded Foundry haul, no proven three distinct practical homes, no natural survival/harvesting-to-positive-deposit run, incomplete permanent item-by-item provenance after stack merges, and no human balancing/enjoyment or independent CI. Keep the expanded order on HOLD. Re-run `cd web && npx tsc --noEmit && npm test && npm run build && npm audit`, then `npm run preview -- --host 0.0.0.0` for a local preview.
