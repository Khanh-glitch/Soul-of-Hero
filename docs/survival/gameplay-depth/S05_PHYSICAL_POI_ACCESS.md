## What is playable

- The existing Watchtower cache contains the real Vault Keycard. A newly created card is an individual UID with **3 SOH-provisional uses**; inventory inspection and scan feedback show remaining uses. Outside a recognized card gate, a valid class and positive charge are checked before a successful scan, one charge is atomically removed, and the exhausted item is removed. Opening/closing a door does not reroll stock; re-opening from outside requires another scan. Wrong/missing/empty cards fail without spending. Uncharged legacy stacks retain their historical one-use-per-card behavior, not three free charges.
- At the existing Lighthouse generator, one carried physical Fuel Canister starts a **180-second SOH-provisional** local window. E/F on a running generator switches it off, retaining unused seconds; E/F again resumes without another can. When depleted another physical can may be used. The fuel item is the same `fuel_can` used for the W07 motorbike, furnace recipes, and base power. Generator and gate prompts show running/off/remaining/depleted states. No home energy or virtual fuel is borrowed.
- Foundry vault is a card gate; Lighthouse is a power gate. Their existing requirements are independent. The existing Delta Relay `pack.pois` has a card gate and a separate powered gate in sequence; it is **not** a single combined card-and-power reader. The existing general entry, exterior caches, deep caches, walls, loot source identity and loot renewal remain. No colored rooms, cards, spawns, fuses, wires or oil sites were added.
- Door `locked` remains the authored requirement; `open` is physical collision. Each authorized opening closes after **15 SOH-provisional seconds**, or at power loss for a powered gate. Closing waits if a player, living creature, cart or bike occupies the aperture; it retries after the obstruction clears. The documented interior side has a manual free emergency release using the same physical door, so an occupant can exit after an outage or an expired card. Exterior attempts still require the actual card or live connected generator; neither teleport nor a wall pass is used. Doors can also be closed manually when the aperture is clear.
- At the Foundry an existing door was authored over a `PWALL` tile: previously the unlocked sprite could open while underlying collision still blocked the aperture. `blockGrid`, room-wall interpretation and the door tile presentation now treat **that exact existing authored door cell** as an aperture when its door is open, while honoring live terrain mutations. No map tile, room, source position or wall was moved. The existing Foundry radiation rules and mask mitigation remain; the interaction prompt warns only when the current actual tile/zone is already radiation-bearing. No new hazard was invented.

These provide the optional choices Watchtower card → use/save its remaining scans, fuel → home power / motorbike / POI, exterior supplies → enter or skip, limited powered time → loot/retreat/restart, and existing deep loot → physical inventory / research / manufacturing / transport. The browser and tests below do not demonstrate all of these as a natural single journey.

## State, clock and custody contract

`RunState.poiAccessVersion='poi-access-v1'` is set on new runs; `poiAccessDigest` binds built-in Web adapter identity, map ID/revision and its door-side/circuit mapping. Existing runs may acquire the digest when they first use the new system; absence on old runs is preserved. It is an accidental-change guard, not remote anti-cheat. `World.poiAccess` is an additive Web adapter, **not yet a Map-package schema**. Each contract identifies exact door tile, requirement (`keycard` or `power`), cardinal interior side, card class (`vault`, with green/blue/purple representable when authored), and for a powered gate the exact generator tile. It is resolved by coordinates rather than POI-name heuristics.

`Entity.locked` remains unchanged for new recognized gates. `Entity.poiDoor` stores version, automatic-close timestamp, scan count and last scanned card UID. `Entity.poiPower` stores version, original fuel time, current bounded run start/budget/expiry, and optional paused seconds; `power` reflects on/off. `Stack.charge` is per-card and not merged or split into duplicated charged stacks. Scans, fuel (including source UID), pause/resume, expiry and door closure use existing receipts; successful intent IDs retain existing replay protection. Checksums and a bounded receipt ring do not prevent deliberate rollback of all local copies.

A generator's expiry and a door's closure are boundaries in the existing `advanceWorld` chronological loop, used by both online `syncWorld` and offline `settle`. The same absolute run time and saved budget are used after reload; pausing conserves the remaining fuel time. Input first synchronizes the world in the UI. Obstruction deferral does not extend the generator budget. The run expiry/normal wipe remains unchanged.

**Legacy migration:** old snapshots are not rewritten or recharged. A previously removed lock stays removed, and an old generator already permanently unlocked by the earlier implementation remains grandfathered; it is not charged a second can to preserve that legacy access. Old doors still locked use the new bounded mechanics on their next legal action, and an uncharged legacy card is consumed once. This exception is deliberately not presented as newly earned bounded power. New saves pin authored gate requirements and reject altered access digest, invalid card state and malformed power intervals. Existing UID/rare stock is not reminted.

## Scope and Map / A3 handoff

Built-in Web Foundry and Lighthouse sides are derived from their actual authored partitions/building entrance; Delta Relay sides and generator are derived from the `PoiDef` wall/door/cache coordinates. These are **Web gameplay adapter assumptions**, not owner-certified geometry. Verify the full approach, player/building occupancy and return paths on the actual Map before cross-owner acceptance. The imported Veyra layout has no `World.poiAccess`; locked gates and generators without a contract fail closed before any card/fuel debit. Existing legacy doors whose locks had already been cleared remain grandfathered.

Map must publish, version and validate the exact gate tile, axis and **interior exit-side region**, interaction stand points and clear paths, matching circuit generator identity, requirements and accepted card class for every imported gate, including geometry changes and dynamic blockage rules. No named-site heuristic or fake coordinates are sufficient. `RuntimeMapPackage` / `GeographicHandoff` do not yet carry this access schema: Map/A0 integration must explicitly extend the package, validate collision and identity, and migrate run-pinned digests without discarding a player or loot. A3 must approve card sourcing, scarce fuel/runtime, optional alternatives and expedition tradeoffs. Native requires equivalent UID/custody, clock, closure, digest and legacy migration on a shared source SHA. No native or cross-owner parity is claimed.

Limitations: current maps do not author colored card tiers, a combined card-plus-power reader, fuses/resistors, site-specific access hazards or an authenticated Veyra circuit, so those are **not implemented by invention**. Existing POI loot and environmental systems remain their own authorities; natural access, risk, every obstruction and long-duration balance remain to be reviewed. Generated Web safety metadata is provisional. Automatic interior release is an SOH safety adaptation, not a historical LI claim.
