# SOH — Two high-value systemic design candidates: joyful returns after offline + causal ecology/weather/day/night
Status 2026-10-30: **RESEARCH / CT DESIGN PROPOSAL**, NOT final game clock, two years, weather severity or production numbers. **USER-LOCKED D059 is separately confirmed** in `DECISIONS.md` commit `79e346109d45f1452814528a32ee30f3b1d8376b`: sheltered offline hunger can drain with real food usage and HP drop to 1 but starvation alone cannot kill inside a valid home; unprotected wilderness still has lethal starvation risk with one death bag and clear forecast. D055–D058 unchanged (14 real days incl offline, all gameplay reset next run, profile achievements/run history only, per-run flexible starter guide and broad random safe spawn). New user proposes **NOT YET VOTED**: online return surprises (fruit matured, research complete, ingots finished), possible 2 world years across a 14-day real season while 2 real hours ~3 in-game days, realistic swamps/heat/frost/radiation/day/night/fog/weather/disasters. **DO NOT** lock two years or automatic offline total-world simulation based on this example.
## A. Central user value and test of any proposed system
Each quit is a **player-authored commitment** (plant seeds / pour ore+fuel / pick one research project / stock rations / choose home location). During offline, authorized physical setups advance to verifiable outcomes until material, fuel, capacity, time, climate or per-season expiry stops. On return, show a **positive truthful world-state delta with a reason-based bottleneck** and 1–3 actions the player can choose next, not daily login prizes or passive infinite AFK power. The satisfaction is anticipating a planned outcome and discovering consequences, NOT a random gift.
Game cycle: choose tradeoff and source → physically prepare resources & station → choose how long to leave, see reliable forecast → return, see what truly matured/finished/used/stopped/changed locally → use results in player-chosen new route/quest/skill. Do not auto-play POI, Core finding, hunt, combat or construction.
Research literature offers useful *pattern*, not SOH source truth: https://www.gamedeveloper.com/design/the-rise-of-games-you-mostly-don-t-play (anticipation/positive idle progress); https://jichenz8.wordpress.com/wp-content/uploads/2018/10/61bf2-villareale_fdg19_socialidlegames.pdf (timed setup/return can motivate strategic choices); https://wiki.dragonscapeidle.com/guides/offline-progress (offline farm grows but automatic replant requires extra unlock; production stops when resources are gone); https://uyllii.com/blog/offline-progress-idle-game-closed-form/ (same online/offline logic and caps; anti-compounding exploit). Avoid importing their arbitrary caps to SOH.
## B. Resolve time arithmetic before deciding '2 world years + 3 days/2 real hours'
Known 14 REAL DAYS=336 REAL HOURS. Proposed 3 GAME DAYS in 2 REAL HOURS means 1 GAME DAY/40 REAL MINUTES, 1.5 game days per real hour. **IF world time advances continuously including offline**, 336h → **504 game days**, approximately 1.38 Earth-like 365-day years. Full two 365-day years (730 world days) across 14 real days needs 1 game day per **27.62 real minutes**, hence ~4.35 world days per two real hours, not 3. If time advances only in-session and user plays 2 real hours/day ×14d=28h, 3 days/2h yields only **42 game days** per run, not 730. There is NO single fixed 365-day world clock satisfying all three constraints; user example is exploratory, not mathematical commitment. A fictional 252-day SOH year would satisfy 2 years/14 real days at 40min/game day, but 4 conventional seasons would last 63 game days=42 REAL hours=1.75 real days each, so ordinary users away ~2days may MISS entire weather season. Not automatically good user experience.
**CT recommendation:** keep **14d real-calendar season clock** separate from a configurable accelerated in-world day/night of ~40–60 min per world day (test candidate), and decide separately how many *ecologically meaningful* climate periods fit inside the 14d run. Favor testing **one legible climatic year/4 seasonal phases** (each ~3.5 real days) rather than 2 climatic years/8 phases (each ~1.75 real days); there can still be hundreds of fictional sunrise/sunset cycles via other time conversion. Don't call four days 'spring' if user observes it change overnight without a plausible virtual-world calendar; deliberately pick one world calendar and normalize physical crop time. Fewer meaningful seasonal shifts better than two flashy high-speed years. User must choose if literal 2x full climate-year cycle is more important than the 2h→3 world days comfort target after seeing schedule.
**Technical clock roles**, one A0 time authority:
- `run_real_utc`: monotonic best-effort elapsed real UTC, 14d deadline, remains counting offline; protects rollback best-effort (fully offline device clock cannot be tamper-proof).
- `world_day_phase` and `world_date`: world-calendar projection, configurable fixed scale with season/climate region, can advance by real elapsed time offline while rendering engine is inactive. The visible day-night cycle uses this projection, not repeated expensive frame ticks. Never advance full monster AI, player movement, boss, terrain damage or auto loot while app off.
- `operation_time`: EVERY process registered per source/action (ACTIVE-only source cooldown vs REAL-elapsed offline-eligible house craft/crop/learn). Each has distinct clock domain, no hidden auto-switch. A3 current 1800 ACTIVE SEC source cooldown remains unchanged until explicitly renegotiated; one app-offline day does not refill ordinary loot caches on re-login unless separately approved.
- `weather_climate`: deterministic region/biome+altitude+season+weather-front model derived from same calendar, not an unrelated random clock or independent dice roll on every map cell; stop progression at run deadline.
## C. Offline progress capability matrix — proposed, not locked
| System | Offline proposed | Bound / rationale |
| --- | --- | --- |
| Crops/orchard | YES growth to maturity, optional flowering/fruit stage and limited yield; NEVER auto-harvest/replant without paid equipment and separately authorized mechanics | water/soil/season/temp, capacity, slow perish with warning; don't punish ordinary absence by mandatory daily harvest |
| Smelter/furnace | YES only existing physically loaded queues | iron ore+fuel+speed/input and output cap; when fuel ends stop, never infinite output, no background ore mining |
| Research station | YES for accepted paid queued task | choose tech/valid sample+spares, advance clock, on complete set result/ready-to-claim, no automatic chained next research or fabricated source Core |
| Food processing | YES if real ingredients/fuel/storage | finite batches, quality and expiry if feature exists; no infinite passive food |
| Water collector | YES from actual regional precipitation/dew and clean collection parameters | tank capacity and filtration, weather history known; no unlimited free water |
| Fed sheltered player | YES satiety decrease + real ration consumption under D059; no starvation death in valid shelter; may be 1 HP | A0 owns atomic, no independent UI consumer |
| Offline sheltered home destruction by AI | NO under current decisions | player-in-world away while APP OPEN is a distinct legitimate tracking/attack system |
| World regional ecology | YES continuous calendar progression, bounded nonfatal weather/stages | weather may change plants, floods, roads, water level, crop growth, never fake infinite loot or kill unprotected main home without separately chosen disaster policy |
| A1/A3 ordinary loot/source refresh | CURRENT ACTIVE-ONLY (source-specific) | do not silently convert to wall-time replenishment |
| Monster hunting/POI exploration/Core rare finds | NO | only actual user-input actions and/or separately authorized staffed structures can earn them |
| End of run | stop all advance at 14d real deadline, archive results D056 then new run zero | no completed offline output from after expiry or carryover |
**Production vs active dilemma:** Plant cycle after 18h off at 40min world-day implies 27 fictitious days elapsed, which may be enough for plant maturity; must decide crop days/minutes consciously, not plug 2019 real plant values blindly. Allow a crop to remain harvest-ready across ordinary 1–2 real days, unless player chose fragile short-lived crop and could foresee spoilage. Farming should be rewarding to return, not permanent attendance pressure. Research completion must be an actual paid technology change or at least a claimable result, not random 'tutorial task finished' gift.
## D. Re-login visual and functional acceptance
On login after e.g. 18h away, SHOW ACTUAL 2D HOME GARDEN bearing fruit and a filled furnace output slot, not just a text alert; same resolved SaveService authoritative data in on-screen UI + world. A returned forecast/report: eligible elapsed offline duration, season time remaining, what newly completed, actual units and why stopped (fuel empty, no water, output full), exact provision consumption / HP=1 floor, recent noncatastrophic weather and localized world changes. No invented items or one-off 'daily reward' screen. Favor quiet diegetic animations (glowing forge, crops hanging) and a concise optional report; control of camera/player immediately returned, not blocking modal. A6 native 720/1440/2160 readability, A1 lighting/weather world, A4 exact Gold source priority. No remote Discord/social login requirement; D057 player guide can teach starting productive workflows without hard-gating.
## E. Regional realistic weather and traversal model
Use 2D top-down logically **meaningful causality without high-fidelity 3D weather CFD**. REGION environment state from local tile geology/altitude, drainage/water, canopy density, biome, pollution source, day/night, forecast front and seasonal modifiers.
1. **Swamp/mud:** speed penalty emerges from wetness, water depth and substrate, not a fixed 'swamp -30%'; boardwalk/boots/bridges/cart wheel width can mitigate; some routes flood only after preceding rain and retreat must remain possible. Avoid making swamp movement slow enough to be irritating all the time.
2. **Heat/drought:** exposure and thirst from daytime sun, air temp, wind and gear insulation/ventilation; shade/night/tent/water improve. Home heat from furnace may help in snow but hurt in hot area. Thermal insulation can have tradeoffs, not one universally best armor.
3. **Cold/hypothermia:** low temperature, rain-wet gear, wind exposure, altitude raise cold load; coats/roof/fire shelter, warm food, terrain mitigate; frost damages crops and blocks lakes seasonally with a physical visual state. Don't punish without readable cues.
4. **Radiation/toxin:** primarily spatial high-risk source from physically authored waste/ruin/source, with exposure accumulating over time, mitigated by mask/gear/antidote; **do not equate radiation with hot climate** or assume rain creates radiation universally. Plume or contaminated runoff only if map geology/source justifies.
5. **Fog/night visibility:** actual optical line-of-sight and local light/projection range, silhouettes retain minimum readable path/Hero, monsters use separately modeled senses/noise/scent; dense fog localized at dawn/river/wetland and lifts with heat/wind. Gold cast has adaptive map dimming without rewriting source VFX and without crippling navigation. Pixel-perfect scene light, no indiscriminate opaque gray filter.
6. **Wind/rain:** rain falls by regional weather front not random pixel-by-pixel, affects soil moisture, collectors, footprint age and water/runoff, possible movement/visibility friction; wind affects fires, smell trails and storms. Player should understand forecast, e.g. clouds/rain arrows and shelter value.
7. **Disasters:** scientifically plausible in-game causal weather chains and warnings: multi-day heavy rain + basin drainage=flash flood/waterlogged lowland/route closed/new stepping stone; drought + heat + high wind = wildfire risk; snow accumulation + slope = avalanche; electrical storm + metal/wet = localized lightning. Introduce gradually and graphically legible, always bounded and usually route altering more than deleting earned progress. Explicit user approval REQUIRED before catastrophic off-app base destruction. No arbitrary random spawn killer, no untelegraphed hero death during offline. Recovery routes/repair tradeoffs MUST exist.
**Seasonality is REGION-SPECIFIC**, not all map tiles simultaneously snow-covered: highlands cold longer, tropics wet/dry seasons, swamp flood cycle, temperate orchard flowering/fruits. Same global calendar but spatially varied responses; climate fronts move through adjacent regions with plausible direction, local procedural variance deterministic per run. Static A1 16px geography and authored source instances remain fixed; dynamic masks/props/water flags in separate world state.
## F. 'More realistic' requires cross-system conservation
- Rain helps crop water but may reduce bright vision and accelerate footprints fading; rain destroys campfire if not under one simple roof; fuel wetness slows burning but covered stack stays protected.
- Flood takes a low shortcut but reveals an alternative safe highland route and maybe reeds/water fish, not random permanent softlock.
- Cold makes seasonal equipment meaningful and source-limited, but rare Core first use remains satisfying; neither magic all-weather immunity nor five persistent gauges.
- Volcano/hot region requires hydration/thermal tradeoff and can make night expedition attractive; long trips require basic clean water source and vehicle load.
- Off-app crops still grow by actual rain and season; smelting requires real fuel even though it is offline; prep state and A0 receipts match. No free infinite resource cycle (crop→fuel→food→crop) for an unattended farm unless it's a separately intentional, balanced automation system.
- User-controlled monster summon while actively playing may be affected by weather/footprints; quakes/floods NEVER mint Score or loot from repeated same source. No independent apocalypse while user cannot act.

## G. Test grids and implementation safeguards
**Time compatibility tests:** D055 + D056 + D059 14days wall UTC, clamp event finalization, 40/55/60min candidate world days, 1 vs 2 climate cycles over 14real-days, with login gaps 2h/18h/48h and once-after season end. Quantitative: at 40min/world-day, 18h offline =27 world days, 48h=72 world days; 2 full SOH 'years' of 252world-days each can happen in 14 real days, season phase each 42 real hours, leading to likely missed season. 365-day year target 2×=730 days/336h =>27.616min world day, 4.346 day/2h, contradicts proposed 3days/2h. 2hr active/day for 14d gives 42 in-game days if only active clock. An example full-world 365d/year 40min/day yields 504days ≈1.38year and four seasons in ~10.14real days (as calendar seasons), but user shouldn't be tricked into 'exactly 2 years'.
**Atomic settlement tests:** if 18h off: crop due stage, oven 8 iron ingots (only if exact paid ore+fuel+output), research one unlocked project, 4 rations consumed (only if actual source amounts), rain fills water to tank cap, other latches unchanged; repeat reopen 10× no further yield; crash at each write boundary all-or-nothing. Verify world crops visually correspond to items and state, no retroactive Gold Core from idle time; storage full stunts chain; reaching final season cutoff stops reward. Weather change is deterministic over interval, doesn't have to re-run 27× day/night frame loops.
**Weather narrative tests:** heavy rain raises swamp depth and lowers speed, boots/boardwalk change, retreat still valid; dense fog shortens sight but preserves nav cues; night lantern helps, Gold original readable; early spawn never lethal during climate phase (A1/A3 region spawn gates), frost protected greenhouse grows differently; drought boosts wildfire risk ONLY with combustible fuel+wind, no random house wipe while app off. A7 negative tests prevent anti-farming, clock rollback, weather duplicate source production, region unload changing timers.
**Architecture owner:** A0 owns world clock/season, save profiles and all receipts and event ordering, offline reconciliation. A3 owns recipes/inputs/outputs/season-sensitive source rates and resource conservation, only A3 may authorize specific time rate or yield. A1 authored terrain/weather regions/biomes, safe nav/collision and dynamic-overlay semantics. A8 POI seasonal physical site cues. A6 return digest and forecast/visual HUD. AVFX/A4 exact Gold and adaptive terrain contrast. A7 independent native OS restart/season and weather tests. No second SaveService, no massive per-frame simulation off-app, no unauthorized asset source.
