## P7 — enemy navigation/structure destruction
**Decision: ADAPT EXISTING; implementation DEFERRED until existing A0 native navigation + full shelter/clock/SaveService foundations.** SOH CT-07 construction already explicitly promises real collision and AI-navigation consequences, with CT-08 energy/doors and optional base-defense designs; this is not a new AI architecture. Actual `SurvivalStructure` materializes authoritative persistent collision/doors, `SurvivalBuildSystem` recomputes geometry/room topology and authorizes paid placement. `SkeletonEnemy` steers along collision normals for simple wall avoidance, but this is not a structure-aware path planner. We did **not verify** a runtime enemy choosing among open path/closed door/breach, attacking a player-owned structure, persisting its damage or rebuilding correct navigation after load. No implementation sign-off.

**Product proof-of-value**: a real player makes consequential choices about building materials, doorway location, gates, line of sight and repair; enemies sometimes detour rather than always hitting nearest obstacle, with clear telegraph and reasonable break-time/reward. Never impose offline raids, destructible mandatory dungeon path or unavoidable griefing.

**Future native tests (not yet run)**:
1. Same enemy/target/seed: open door, closed door with alternate walkable route, blocked route with damageable structure. Assert goal choice/path-cost/decision latency and feasible avoidance vs breach.
2. Construct during chase, open/close, damage/destroy, rebuild/repair; authoritative collision and AI path updated boundedly and nav-revision under proper owner.
3. Idempotent structure damage/destroy event, saved durability, reload/restoration of physical collision/room and navigation; no duplicated loot, refunds or structures.
4. No enemy trapping Hero inside starting shelter, protected 10 dungeon entrances still reachable, no forced/offline PvE raid, explicit opt-in base-defense activity only.
5. Validate frame-time and high-density collision/nav caching, enemy readability at 720p/2K/4K and actual normal-input base-defense choices.
Owner boundary: A0 world/physics/SaveService, existing combat owner for enemy AI, A1 routes, A3 defense economy, A6 telegraphs. The label A5 is an older workstream or optional S6 deep-POI design, **NOT an additional staffed bot**.

## P8 — ExpeditionSummary / expedition effectiveness
**Decision: ADAPT EXISTING CT-12 and A7 measurement workstream; research PRIORITY HIGH for gameplay decision quality but does not block current runtime implementation.** Blueprint CT-12 explicitly plans ExpeditionMeta/replay/persistent home. Workstream A7 is unstaffed; its balance/QA responsibility is handled through A3's simulations + independent Control Tower review. GitHub code search/Blueprint did **not** reveal an exact existing `ExpeditionSummary` schema; the name in the addendum is NOT an approved interface until located in Development (2) and mapped to existing SOH source/contracts.

**Minimum proposed read-only `ExpeditionSummary.v0` contract (proposal, not verified existing schema):** `run_id`, `world_revision`, `started_at_active_tick`, `ended_at_active_tick`, `route_ids/discovered_cells`, `item_inflows` by immutable event/source ID and quantity/unique instance, `item_outflows` by consumption/death/transfer (do not conflate lost with spent), `home_deposited_delta`, `death_and_recoveries`, `hazard_exposures`, `POI_discoveries`, `equipment_and_core_uses`, `carry_capacity_and_transports`, `conditions/flags`, `evidence_scope`. Must support replay-safe event provenance and minimize save growth by derived rollups/snapshots; do not create a competing SaveService. Outbound UX should be discovery-filtered and avoid revealing undiscovered locations.
**Core metrics**: `net_recovered_value` by A3-authored price/value assumptions (show raw quantities too), `loot_per_active_minute`, `net_base_deposit_per_active_minute`, `repeat_travel_cost`, `loss_at_risk`, `damage_deaths`, `new_access_or_recipe_knowledge`, `unfinished_goals`; separate meaningful outcomes from uncalibrated dollar scores. User choices/counterfactuals: same A1 route with vs without cart, outpost/kit/filter/skill, then compare delivered resources, fatigue/death, alternate objectives, return burden. **No fabricated gameplay data/human playtest.**

**Future event/reconciliation tests**: no double-counted grant/transfer/recovery; death-bag lost vs recovered; same specimen transfer returns original unique instance, researching specimen is not loot generated, inactive time excluded, interruption/reload produces one summary; exact sequence source-checked against real A0/A3 event receipts; absent telemetry fields correctly marked UNKNOWN. Data collection must not turn into busywork for player; UX can display concise expedition outcomes later via A6 on approved read-only DTOs. No A7 new agent, no background recurring service.
