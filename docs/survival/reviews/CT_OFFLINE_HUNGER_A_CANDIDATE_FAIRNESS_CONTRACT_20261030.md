## Main design diagnosis
Why A can be meaningful: hunting, food storage/preservation, water container, farm, kitchen, properly built one-storey enclosed shelter, bed and early guide quests gain real usefulness **before** a player quits; you can embark on distant trip vs invest in stocked home; 14-day real time makes resource planning matter. Why it can be unfair in SOLO OFFLINE: user has no online teammate to feed/rescue character, ordinary absence is not misconduct, device crash/power outage can unexpectedly lock in outdoors, naive death bag might be inaccessible, one long absence already spends scarce 14-day season and could destroy a rare Core without an action, login frequency coerces players into chores. The desired feeling is realistic consequence of **preparation**, not recurrent login duty.

## Recommended A-SAFETY: strict offline need decay plus non-free preparation and a narrowly-defined rescue floor
1. Real offline `satiety` decay on a separate configurable rate. Count elapsed UTC only up to season end and only once since `last_applied_at_utc`. Offline hunger vs in-game activity hunger separate curves. Do not add unsourced water/fatigue/cold/heat/wound/AI/offline farm simulation from this choice.
2. **Player-provisioned food budget**, never free: at valid physically occupied one-storey shelter/bed/room with an explicitly selected ration container, offline upkeep can take **only authorized food servings physically stored in that container**, applying spoilage if designed; owner inventory receipts and same source storage authority A0/A3, atomic to avoid duplication/cost-less satiety. Players can stock enough food for planned absences, but scarce supplies/time/gathering are consumed. Optional field rations could last a short absence if explicitly prepared, but never auto-create provisions.
3. Display survival forecast: before quitting and in status overlay, current hunger, offline loss rate, predicted time until critical; if shelter+rations, stock-derived predicted safe duration and food requirements, with a specific red danger when an unsafe wilderness logout is predicted. Forecast recalculates on hunger changes/gear. No false 'safe' if pantry not actually valid, crops not mature or food reserved by another station.
4. **Lethality is the genuine unresolved USER feeling decision**. Proposed fair distinction:
   - With valid shelter: consume rations; if exhausted, hunger reaches zero and HP declines at controlled offline rate to **critical 1 HP floor**, preserving run/possessions, but *no heal*, no free pantry, hydration risk on return if separate choice. This rewards building a refuge, not logging in every day. The player still loses the run's real calendar time.
   - Without shelter (or in high-risk wilderness): if hunger hits zero after the predicted duration, **death may happen offline** following clearly displayed risk. Generate ONE durable death bag at actual logout location with unique item IDs, respawn with normal safe/bed rule on return, recovery before season end; no repeated corpse loops as clock accumulates; ensure bag can actually be accessed and original save cannot dupe.
   - If user wants *truly uncompromising A*, remove shelter floor but retain fully provisioned house, logging warnings and corpse custody; test whether users see it as fair. If user wants *no offline death anywhere*, that is a B-style variant (decay meaningful but nonlethal) and should be acknowledged rather than mislabeled A.
5. Do not model offline monster AI raids/footstep hunter attack/building damage unless user separately authorizes. 'Player away from base while actively playing' is NOT 'app offline'. No negative offline HP consequences from unapproved winter/poison/weather until designed. Never allow a background production/crop timer to create free food instantly at same tick as retroactive hunger charge without defined transaction order.
6. Do not use game close/quit UI action as an exploitable switch. App kill/crash and deliberate quit save real location/state. All offline consequences apply on next run open as ONE idempotent deterministic transaction; no clock rollback exploit. Clock authenticity fully offline cannot be tamper-proof, document reasonable last-seen bound and graceful error state. Season expiry dominates: if current date ≥ deadline, archive end season once and do not calculate a chain of hunger deaths after season is already over.
7. New player D058 geographically random safe start must have reachable edible+water basics and starter-guide quest explaining offline prep without giving free indefinite food; first logout after accidental short tutorial interruption should not yield a surprise death. No artificial obligation to sign in daily; player gets clear means to stock multiple days of provisions if resources reasonably accessible.
8. Definition of fairness: for every death/loss, there must be a specific action, resource deficit and UI-known time budget the player could reasonably foresee/prevent, plus valid recovery route and no authoritative receipts duplicated. A system that simply drains a calendar clock with no viable provision source is a time tax, not gameplay.
9. Compare minimum 3 simulated return gaps (1h, 24h, 72h), three sites (house provisioned, house unprovisioned, wilderness), two starting states (new spawn without house vs established well-fed run), and close at t0+14 calendar days; no false human playtest claim. Measure preparation cost, number of food-crafting actions needed, survival probabilities, impossible recoveries, login frequency demanded. Require real native OS process reload and different clock conditions before any gameplay acceptance.
