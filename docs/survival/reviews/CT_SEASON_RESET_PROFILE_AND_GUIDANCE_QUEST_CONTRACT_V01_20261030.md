## First-run onboarding / replay quests (D057)
Quest narrative presents NEXT OPTIONAL RECOMMENDED VERBS, not one forced tech tree:
- orient and recognize a useful nearby resource; gather by normal input
- establish shelter and chest; place functional door/wall/bed
- transfer goods and turn safe salvage into useful workstation/tool/recipe
- read hazard/approach POI, bring items back; optionally pursue deeper risk
- let other quests offer voluntary objectives as per chosen strategy; not artificially required to unlock free exploration, basic building, recipe or Core drops.
Every quest should define `quest_id`, hint/copy, prerequisites **for hints only** (unless justified in-world), objective proof against authoritative run events or current world state, `reward_policy_version` owned by A3, `claim_receipt_id = run_id + quest_id`, and optional hidden contextual guidance for experienced players. UI renders beginner full hints and experienced compact optional checklist, but this is a **CT UX proposal**; user has locked the underlying optional nonblocking reward-bearing quest reset, not exact menu.
**Examples needing tests**: build a chest BEFORE inspecting the quest screen; the completed genuine chest qualifies (do not require new one). Player takes a POI route first before following the home task; normal world travel still works. The same quest cannot grant twice on same run after crash/reload or claiming from two panels. On NEW run the quest starts fresh and reward may be earned once again. No fixed reward item quantity in this contract. Ensure optional fast-forward and hides do not accidentally grant rewards or make new player lost.
