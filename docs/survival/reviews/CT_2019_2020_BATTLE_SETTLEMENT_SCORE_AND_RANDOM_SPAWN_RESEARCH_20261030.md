## H1 — July–Aug 2019 original battle settlement ≠ general activity-weighted score
Official publisher FAQ [2019-07-30] https://hero.yingxiong.com/info/2019/0730/6973.html : five modes including 15 real-day standard/PvE/guard/solo and 7-day blitz. End-game settlement rewards tied to taking Restart Badge (`重启徽章`), a late-game world item/claim returned to territory cabinet. Run resets after end; original mode had explicit rare-blueprint/skin exceptions, but SOH user D056 **does not** retain recipes/Core. FAQ says character level up through cutting trees/killing; distinguishes within-run character level and reset account reward. No single universal score = building+exploring+boss+core formula is documented. Official publisher 2019-08-07 https://game.xiaomi.com/viewpoint/1103968488_1565170379066_13 states badge in last ~3 days, return it to cabinet to get settlement gold multiple/badge cosmetic reward, not all activity counts.
## H2 — September 2019 special 夺榜 MODE (30 real days) has structure-related score, not flat construction reward
Official publisher patch [2019-09-26] https://hero.yingxiong.com/info/2019/0926/7229.html : leader-climb `夺榜` is a **distinct 30-day ranked mode**. Cabinet attacked/destroyed triggers score assessment based on building/facilities, excludes wood and stone maintained structures/facilities; score determines ranking + top-10 settlement gold. Also limited cabinet destruction, damaged protection, no passive arbitrary build points specified in this 2019 note. **Do not import model to SOH**: solo user has no competing cabinet raiders; simply assigning score to a constructed wall is exploit-prone and doesn't capture good design.
## H3 — November 2019 战局等级 battle level IS an independently real score-like metric
Official publisher patch [2019-10-31 / effective Nov 1] https://hero.yingxiong.com/info/2019/1031/8033.html : `战局等级` (battle level) cap revised to **15**; settlement `战局结算等级` under level 5 gets **no reward**, level also unlocks recipes and max HP within run. This is strong candidate for user's memory of one battle result number, but it is a **within-run level**, not verified universal single battle score formula. Earlier July 2019 FAQ references max character level 100 (different snapshot); do not harmonize as same level cap.
## H4 — January 2020 leaderboards were multiple separate activity scores, reset weekly
Official publisher [2020-01-08] https://hero.yingxiong.com/info/2020/0108/8968.html : challenge score from downing military helicopter/tank, miner score from mining stone/iron/sulfur, scavenger score from barrels/supply/weapon/airdrop crates, cosmetic-skin score; except skin, weekly settlement resets. These are separate leaderboard domains, **not** formula for one 15-day season end screen.
## H5 — August 2020 separate persistent Action Base score is NOT battle-end score
Official publisher [2020-08-26] https://hero.yingxiong.com/info/2020/0826/10634.html : permanent separate Action Base (not resetting), `基地积分` (base points) obtained from **any actions inside base**, ranked weekly. The same source describes player-base power from recipes/construction. It should **not** be copied as SOH's 14-day battle result because D056 fully resets the base and it rewards unbounded activity.
## H6 — Important out-of-era control: January 2025 S2 ranked model
Official publisher [2025-01-15] https://hero.yingxiong.com/info/2025/0115/14120.html : S2 ranked points broken into battle, daily, home-defense and settlement; battle/daily/defense have per-day caps; same target player kill/cabinet breach can score once per day; structures/material/amount in cabinet accumulate guard points per hour; remaining points partial at settlement, badge has explicit score in classic/unlimited modes. This is a useful **anti-farming pattern** (caps, source identity, no repeating same victim), but **cannot** be described as a 2019 mechanism or proof of a complete anti-exploit game design.
## H7 — User's spawn matches documented gameplay, not a new art-inspired guess
2019-era guide republished 2020-06-03 https://news.4399.com/zhytgz/xinde/m/895633.html says **first entry randomly spawns on map** (`第一次进入游戏，是在地图上随机出生`), recommends choosing strategically where to build based on roads/resource sites, and mentions a guide quest shown near top left + survival manual, with rewards like territory cabinet, bedroll, workbench, code lock. ## Design adjudication for SOH
**WITHDRAW** previous `Điểm hành trình` score title, 8420 sample and arbitrary category weights. Achievement/result record D056 still USER-LOCKED, but whether it contains *one comparable scalar* or `battle_level` milestone or unique expedition objective score is **OPEN**, as are numerical weights. Do not turn "boss kills", "visited places", "Core found", or "buildings built" into automatic awards without precise semantics; specifically:
- Rebuild: only durable, net-effective, unique state/capacity/useful infrastructure over time could hypothetically qualify, capped per site/quality and net-cost, not placement events; **not approval for any metric now**.
- Boss: first completion of identity-gated objective separate from repeated loot-source kills; boss repeated drops can remain useful to economy but do not automatically increase a season badge.
- Exploration: genuine authored region/site discoveries and meaningful interaction proof via normal input, not entering grid cells or driving around in circles.
- Core: distinguish first unlock of genuinely distinct skill identity vs each dropped instance, test actual cast/use; no fixed rate.
- Alternative is **no aggregate score**: present a transparent historic record of a run's end with a few unique completed goals and player-preferred statistics + earned special end-of-run objective if wanted, without inventing global rank. Compare the user taste to this after showing sourced screenshots/rules of historical badge/battle level; do not force a contrived scalar merely because "one number" is vaguely remembered.
- All result/achievement data from authoritative A0 committed events, run/target/POI/item identity and exact season; no UI side effect scoring, no duplicated result on crash/restart. Scores not an authority for economy or Core grants without separately approved reward policy.
## Safe distributed start — user-locked direction, CT-selectable technical rule
Every new **run** (D055/D056) chooses one point from a **geographically broad eligible spawn distribution** of authored valid walkable cells in different safe biomes/regions. A location is eligible only if no immediate toxic/radiation/cold lethal hazard or unavoidable enemy ambush; navigable escape routes; available ordinary safe basic wood/stone/food/roadside source in reasonable traversal; no boss/enemy aggro at emergence; no wall/roof/chunk/POI blockage; no water/no-surface/infinite fall; no forced proximity to an existing structure or high-tier unique rare loot that causes unfair instant advantage. Do not exclude all interesting terrain — variety and regional tradeoffs are desired. Weighted/distance-stratified randomness should avoid all runs clustered in one corner, while still being truly stochastic and broad. Fixed reusable geographic map, not procedurally scrambled POIs; world geometry/runner chunk coverage and save run_id must agree on valid spawn. A0 owns actual spawn and new-run seed/custody; A1 owns safe geographic candidates, A3 nearby affordable starter resources, A7 independent native acceptance. Emergency bad-cell recovery does not silently spawn lethal or teleport through blocked POIs. No predetermined selection menu, no fixed universal home town. Death/bed respawn is a separate rule.
