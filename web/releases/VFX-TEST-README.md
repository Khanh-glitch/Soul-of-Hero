# SOH VFX test build

Build: `cd web && VITE_FX_TEST=1 npm run build && mkdir -p releases && cp dist/index.html releases/SOH-VFX-TEST.html`. Open that HTML directly in a browser; internet is not required. This generated HTML is tracked on the review branch so the user has a durable direct download. It is a test build, not a production release.

Choose New run → Begin the 14 days. The test run has 10 physical instances of each of seven Creator Cores and four legacy Cores in its scrollable inventory, Creator Cores initially loaded with 40 Basic / 12 Refined / 4 Signature charges, legacy Cores at their normal full charge. Keys 1–7 select one of each; LMB, hold/release Q, and hold/release E use abilities. Spirit E requires selecting discovered legal ground on M map first. The QA build uses a separate IndexedDB and localStorage name, so it does not overwrite the normal game's save. This loadout is a testing fixture, not normal progression.

## Spirit Q/E manual editor (prototype)

After entering a run, choose **Chỉnh VFX Spirit Q/E (F8)** inside the game at the upper right, beneath the day/status display, or press **F8** to open or close it. Select one of the four layers: Q beam, Q hit, E departure, or E arrival. Values use world-space pixel offsets from the named anchor, a scale, horizontal stretch multiplier, angle in degrees, visual delay and maximum visible duration in milliseconds. Write timing/co-occurrence observations in each layer's note. Edits are stored in this browser separately from both the game save and the production build, and affect **subsequent** actual casts, not instances already running. They change presentation only. A Q beam always ends when the real channel hazard ends or is interrupted; increasing its visual duration cannot extend the ability. One-shot sheets can hold their last frame until the selected duration; there is currently no fade-curve editor.

**Xem lại mẫu** creates a real compositor instance in the game world: a right-facing 130 px beam at the player or, for Q hit, a dummy anchor 70 px to the right. This is not a combat cast. The pause, frame buttons, playback speed and time slider control **only that one preview**; the simulation and other effects keep running. The preview remains until removed, another preview is started, the layer is changed, or the editor is closed. The real E still requires selecting explored, legal ground on the map, then holding and releasing E. The event log records actual Spirit beam start/end, enemy hits and teleport departure/arrival with real-world timestamps and world coordinates; it does not automatically enumerate particles or other layers, and keeps at most 100 entries in memory. Use notes for observations about simultaneous effects; it is not yet a complete multitrack timeline or drag editor.

**Xuất JSON** downloads all four layer settings, notes and the current event log. Send that JSON back for review; it is not automatically applied to the normal game or a later release. **Nhập JSON** restores settings/notes from a compatible export (but does not replay the historical log). Invalid/out-of-range files are rejected. **Mặc định** resets the four settings. Clearing browser storage deletes locally saved editor settings; export first if they matter. The generated HTML must be rebuilt after source changes.

Automated editor checks: `CHROMIUM_PATH=/path/to/chromium node e2e/spirit-vfx-editor.mjs` exercises the actual `file://` HTML, preview controls, JSON export/import, validation and persistence at 640, 1280, and 1564, including a check that the button sits inside the game stage. For real Q hit/beam and E departure/arrival adapter offsets, start `VITE_FX_TEST=1 npm run dev -- --host 0.0.0.0 --port 4188`, then run `CHROMIUM_PATH=/path/to/chromium node e2e/spirit-vfx-editor-events.mjs`. The latter uses a controlled enemy and explored map plus real game input; it is not natural acquisition or human visual approval. Full visual motion/terrain/night/co-occurrence review remains NOT_TESTED.
