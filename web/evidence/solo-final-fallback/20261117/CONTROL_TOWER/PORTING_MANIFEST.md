**Porting caution on test runners (learned the hard way this round).** Solo's sanctioned runner is `npm test` = `vitest run --testTimeout=120000`; the **120 s ceiling is project policy**, and vitest's own default is 5 s. Running bare `npx vitest run` therefore reddens two genuinely heavy integration tests (`veyra05/audit-closure.test.ts` P0-1 at ~6.5 s for a 312 h Day-14 settle, and `tests/wp3-veyra-recycler-integration.test.ts` at ~6.4–7.4 s for a full natural-source → recycler → spend → Floor −1 → save/reload chain) with **no code change at all** — a false red that costs a round to diagnose. Worse, in vitest a per-test `{ timeout: N }` **overrides** the CLI/config value, so "raising" a single test's timeout can silently **lower** it relative to the sanctioned runner (20 s < 120 s). A port must therefore (1) run the target project's own npm test script, never a bare `vitest run`, (2) read the sanctioned `testTimeout` before adding any per-test timeout, and (3) remember the vitest JSON reporter masks a timeout as `STACK_TRACE_ERROR` at the `it(...)` line, so grep the console output for `timed out`.
