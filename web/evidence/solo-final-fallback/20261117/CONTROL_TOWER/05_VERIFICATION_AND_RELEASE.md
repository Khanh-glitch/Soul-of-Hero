# 05 — ENGINEERING ACCEPTANCE WITHOUT BOT-FAKED PLAYER EXPERIENCE
These are release-proof responsibilities of the coding agent. Automated tests verify laws, not enjoyment; human/Creator independently observes real choice, emotional quality and longevity. A fixed route, script or bot-run J checklist is NOT an acceptable proxy for sandbox experience.

## A. Layers of proof — always label
SOURCE/SPEC: Creator/Atlas rule documented; not code.
CODE IMPLEMENTED: actual production caller mutates authoritative state, not a stub or isolated helper.
ENGINEERING VERIFIED: reproducible positive and negative invariants on real code state/UID/time/source/rights, plus reload/offline where relevant.
WEB COMPOSED VERIFIED: current source/build 640×360 via ordinary controls, actual world/camera/feedback, no QA item injection, correct non-fatal input and no hidden UI errors; is a technical interface gate, NOT player enjoyment.
GODOT/NATIVE COMPOSED VERIFIED: actual native project scenes/scripts load and player controls/physics/save; Web green cannot substitute.
S4 HUMAN OBSERVED: real persons voluntarily play, interpret consequences, self-directed goals, independently say what was engaging/confusing and what they'd try; Creator acceptance required.
S5 LONGITUDINAL: several sessions/strategies through relevant late72/336h and run2; practical retention, balance and emergent choices. Cannot be declared from accelerated bot tests. Backend global VERIFIED must have actual anti-tamper/server proof, not local JSON.

## B. Allowed automatic tests (NOT a gameplay route)
- Unit/state machine/property-based tests for source debit, UID uniqueness, total conservation, deterministic seeded event identity, physical access, capacity, anti-duplication, refusal and error handling.
- Adversarial/randomized action permutations (not prescribed progression) to catch double-click, interrupt, cancel, different task order, save/restart, wrong floor, door/power changes, simultaneous depletion, death, moving cargo and Core effects.
- Timed deterministic simulations for *correctness of specific clocks*: growth, fuel, hazard, offline continuity, Ragnarok boundaries, unique finalization; this is engineering simulation NOT proof someone experienced a 14-day satisfying game.
- Browser automation for technical input, frame render, HUD clipping, image decode, FPS/GC, error handling, screenshots at native 640×360, interactive affordances. It must never write “bot completed quest = player experience accepted”.
- Same-sha G1B layout4 and full old save migration, K1–K8 and final 157 item/crafting master revision verification. A forced fixture result must be clearly named fixture evidence, not natural input.
- An agent may use normal controls to discover defects and demonstrate an action in live game, but must not inject resources/character position/hidden flags to claim an emergent player journey.

## D. Tiered effort: never let testing become whole deliverable
During source development run impacted focused tests and TS; capture one physical causal transaction and negative case. At systemic integration milestone run cross-system suites, smoke current build and recheck port compatibility; after source stops changing run the COMPLETE test inventory, app+test TS, production Web build, Godot native (when tools available), save migration, documented offline/h336 test, fair FPS on matching device and security adversarial checks.
When full suite fails, collect exact failing assertion, classify real regression vs inherited defect vs superseded law vs environment; correct material current defect, don't hide it by skip/timeout. When long h336 test times out, profile bounded interval, implement code fix, rerun meaningful representative; do not repeatedly waste a whole iteration on identical failing benchmark.
Scripts verifying specific mechanics are allowed; scripts that represent prescribed player progression or enjoyment are NOT.

## E. Authentic open-ended Creator/human review
Prepare a clean current-SHA standalone build, no dev granted item/teleport and normal controls. Ask reviewers open questions: Which goals did you spontaneously choose? Which alternatives were visible? What caused detours? Was exploration worth risks/time? Were Gold and item icons legible? Did you want to return and why? Did late run feel unfair/empty? What action felt inconsistent? Was performance smooth across different terrain/UI/creature situations? Never coach testers through one predetermined play path; collect free-form decisions and deviations. Observations inform source improvements; do not assert S4/S5 without actual human data. Keep Creator exclusive verdict for visual/aesthetic and alternative noNPC release scope.
An engineering agent can reach ENGINEERING RELEASE CANDIDATE and package everything required for Creator judgement. It cannot self-authorize release, rewrite NPC laws or claim experiential S5 without observation.
