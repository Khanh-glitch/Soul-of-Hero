## A. KNOWN SOURCE BEHAVIOR, NOT JUST PROFILER GUESSES
1. sim.ts advanceWorld around lines 1482–1565 repeatedly slices time against weather, season, fuel, paid machine work, humanEventBoundary, airdrop, power, territory, tender, nature, door, loot and terrain. Within each interval it may recalculate powered devices, walk station/entity lists, run many global world services, then process needs and planning.
2. humanworld.ts humanEventBoundary around line 1599 imposes dt≤60,000ms for every living human, plus more slices for movement, work, nextThinkAt. 336h therefore has at least 20,160 nominal 60-second slices and potentially vastly more due to ~tile and planner events. A fixed 60s cap is NOT an actual causal deadline.
3. tickNeeds loops all humans; usingHumanBed checks all other human bed assignments for each rest check; same transaction may do O(population²) work. humanShelter recomputes map/floor roof connectivity and requires validated door changes.
4. engine.ts allRunEntities around line 3553 still performs Object.values + identity/ID O(entity count) checks on every cache hit and copies returned arrays, despite sorted-view cache. Earlier CPU profile sampled allRunEntities/entityIdSortKey/humanShelter/tickNeeds/stepHumans; profiling alone cannot identify every cost without source tests.
5. human-navigation constructs a new all-entity/block map for every navigator call; resumable A* max 256 per call/48k total may return null for PENDING as well as impossible, encouraging repeated searches. Active-local BFS and global navigation are different planners with distinct access conditions.
6. Current measured h336 P1-5 work ~1,024,222ms fails unchanged 90,000ms Vitest criterion. Old baseline isolated ~93,691ms under concurrent circumstances is NOT a matched regression ratio. Browser SwiftShader frame intervals are similarly NOT matched hardware FPS evidence.

## B. BUILD ONE CAUSAL EVENT SCHEDULER
1. Time authority remains RunState clock and K8 UTC run time. Needs and outcomes use actual hours; fictional day/night/seasons are visual/environment input, not equivalent to hours. Do not add a separate NPC timebase or asynchronously run simulation.
2. Enumerate true deadlines: movement tile/segment arrival; next rational actor decision; rest/hunger/thirst threshold; untreated bleeding and treatment; job reserve/complete/claim; fuel/power/station change; harvest/regrowth; lawful transport arrival/departure; Elder awaken/contact; existing weather/season/terrain/door/POI; h336 finalize.
3. Persist causal intent and last committed phase/event ID in authoritative RunState. Priority queue/read index must be reconstructible from saved records; never the sole authority. Define stable ordering for equal timestamps (existing K1–K8 order, then deterministic source ID + sequence). Do not apply same event twice on reload.
4. Advance to min(actual deadlines,end). Integrate continuous rates analytically across dt; if a biological threshold occurs inside dt, split EXACTLY at threshold, apply damage/blocked work, then continue. A naive large dt which charges all hunger/damage only at end violates chronology.
5. Use region/subsystem dirty state to update ONLY affected indexes. Cache authoritative properties carefully; direct fixture/migration object mutations require conservative rebuild at transaction boundaries or verified fingerprints. Never rely only on markDirty when existing code mutates objects directly.
6. Detect zero-progress loops using (clock,actor/source,event phase) repeats. Repair the cause, log bounded diagnostic; do not mask with 0.001ms synthetic time nudges.
7. Offscreen settlement may use lawful coarser route segments and rate integration; it cannot skip contact checks, fabricate outcomes or ignore a real hazard. When a remote combat event lacks verified geometry it remains PENDING with a specific missing contact, not declared a victory.
8. Keep a single client-facing world and event ledger: render/UI consumes committed authoritative state. Browser framerate never determines elapsed real-hour labor, theft, injury, consumption or survival.

## C. REQUIRED CODE CHANGES
**SIM-01** Remove unconditional per-human 60s cap in humanEventBoundary. Implement nextNeedsBoundary based on exact known thresholds; nextActionBoundary for valid due events; nextHumanMoveBoundary without forcing all humanity to tick per animated frame. Avoid scanning all actors on every unrelated station/weather step.
**SIM-02** BedClaims index: one living actor per physical UID, invalidated by assignment, death, departure, floor/housing mutation and save load. usingHumanBed still checks exact physical bed type/HP/owner/roof/position. Re-test active/offscreen rest and duplicate assignments.
**SIM-03** ShelterTopology by world/floor/actual roof component and door state revision. Short lived read context can serve many resident calculations; door changes and destruction must invalidate relevant components. No shelter or bed granted from chest or visual well icon.
**SIM-04** Build WorldReadContext or equivalent with entity UID maps, region/floor/cell, owners, stations/power devices, actor occupancy and route topology. Construct once per transaction, avoid repeated allRunEntities()/buildEntityBlockMap() calls per route/actor. Support direct add/delete/replace, ID change, archive materialization, migration and world-window changes. If global mutation API is adopted, update all legitimate mutation callsites and test integration.
**SIM-05** Single movement/access adapter for active vs remote: cardinal tiles plus real authored stairs, only lawful doors/card/power/PPE, hazards, collision and carrying; distinguish PENDING_SEARCH from NO_PATH/ACCESS_DENIED. Fair resumable route scheduling must not starve remote people. Re-validate each physical edge and source at actual contact.
**SIM-06** One actor physical position or persisted in-transit segment. Reserve/release occupancy, no duplicate body/cargo while home/expedition; valid window re-entry on same global coords/floor.
**SIM-07** Station/power/garden/territory loop integration: compile deadlines for currently meaningful items, not repeatedly traverse all unchanging stations. Preserve all player-facing processing, historical saved paid jobs and source rules.
**SIM-08** Planner fairness: bounded CPU, priority-aware scheduling, round-robin remote regions, per-intent next retry after blocked state. Do not wake a hopeless search every 6s forever; wake on source/access/risk change or a bounded documented review time. No permanent starvation from one remote plan permit.
**SIM-09** Save revision/migration: all derived event and navigation indexes can be reconstructed; legacy G1B 557→729, historical approved items, 16 pools, personal caches, season state and autonomous jobs remain intact.
