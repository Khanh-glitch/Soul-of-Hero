# First day on Veyra — engineering audit, seed 7606

**Experiment.** Geographic `veyra05-world`, `newGame/startRun`, default spawn, 2026-11-15 08:00 UTC. No actions, staged injuries, extra stock, changed metabolic rates, missing actors, QA or forced travel. This is a **new** run, not the player-assisted Hook kitchen save. Each arm uses the production offline `settle` in one-hour increments. The warm arm saves at h8 without discarding its process-local state; both arms start h8→9 from that same persisted world and use identical subsequent deadlines. The resumed arm uses the checksum-checked snapshot selector in a fresh process and explicitly selects the saved window (`veyra05-at-2048-1600`), not the map menu's `veyra05-world`. It tests engine persistence, not browser storage/UI or frame-by-frame online play. Every hour checks IDs, the needs clock and no replay at the same timestamp. Hook and Greywater are two named, populated communities, not island-wide averages.

**Reproduce** (from `web/`, use a new empty directory, two sequential processes; this takes tens of minutes, not part of default CI):

Empty/missing terminal counts are zero; dead bodies retain their actor IDs. Wall timings include instrumentation and host contention, not FPS, and nested categories must not be summed.

**New late-day time cost:** in the post-access warm arm between h22 and h23, read-only debugger sampling found `h5l` IDLE with an overdue medical `fetch` and a full-store `deliveryWait`. `humanEventBoundary` schedules IDLE `intent.work` reviews with a 1 ms minimum even when `committedRetry` is false; the discretionary planner only accepts missing intents or `work.phase === 'travel'`. This clock can request repeated tiny whole-world slices with no eligible plan. The sampled run was left intact, not accelerated by patching the actor or skipping time. This and the observed cold/warm divergence block a longer endurance claim.

### Next production build: occupied medic and the lost calories

The historical post-access warm arm on `50bb0de` **never produced a warm h24 result**: its worker exited unexpectedly after 2,337 s, still within h22→23. That is not a timeout measurement for a successful day. Two specific causes are now addressed without changing stock, actors, recipe yields or drain rates:

* Westwood `h5l`: [five actual human-event boundaries before/after](westwood-medic-retry.json) from identical copies of the in-flight state at h22.67. A full `c2bt` suppresses delivery of `srik` (one harvested herb); it no longer suppresses independent active job `hwur8`. Before: 1/1/1/1/1 ms, same IDLE actor and overdue medical fetch each time. After: 1 ms starts the retry, 228.57 ms walks the edge, 800 ms on site rejects a dose for the now-dead `h5k`. No delivery, dose, recovery or stock mutation. This is a human-scheduler probe, not an attempt to load an in-flight `settle` as a valid terminal save. `npc-causal-needs` includes both the cargo-only wait and a distinct due fetch.
* Greywater `h2`: [same real pre-access h8 save, same minute and physical berries](greywater-serving.json). Previously drinking from the lot credited **only water**, unlike eating from the identical lot. The item definition, not the reason the actor selected it, now determines the serving's benefits. Three berries uid `s160` for `h2`, two for guard `h6`; total 24→19, `h2` thirst 29.98→41.87. Hunger at +60 s was 46.58 and is now 70.58. No free food or remote sip. Stack consumption and flask **charges** have distinct UID/quantity receipts. Run `SOH_GREYWATER_H8=<original pre-access h8.save> npm test -- --maxWorkers=1 tests/npc-greywater-serving.test.ts` for the matched observation. `npc-consumption` tests either motive, capped healing and the empty flask refusal.

**Controlled Continue diagnostic on the new game code** ([10 one-second samples](navigation-fork-control.json)). Start three separate processes with the same legacy h8 access save, warm for five minutes and serialize. Fork bytes match. Continue normally: first actor differs after 1 s; at +10 s `h3v` has a new harvest commitment for a road wreck that the warm actor already knows it cannot reach. No custody difference in these ten seconds. In the diagnostic-only third process, copying only the three run-local navigation maps to the loaded run (not the actors, clock or cargo) restored the exact whole-run SHA at **all ten samples**. The control is not a shipping fix: even this short warmup held 29,081 discovered points in seven pending searches. Preserve the bounded search/negative proofs compactly, and retest the long fork; do not reset a live game on every save, grant a route on load or declare all long divergence explained.
